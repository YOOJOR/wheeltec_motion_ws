# 论文式前沿探索与启动扫描

2026-10-10 按用户确认更新默认策略为 `paper_frontier`。参考锁定 Co-NavGPT2 提交 `891ba09959278b666ef01a7f8b6c64f8fe8436cc` 的 `Global_Map_Proc.Frontier_Det`、`ros_multi_nav.py` 启动观察与目标兜底流程。本阶段以有种子的随机选择替代 VLM 对前沿的选择，不接 VLM。

## 状态顺序

`等待新鲜 RGB-D/位姿 → INITIAL_SCAN → EXPLORING → 故障 HALTED`。

- 每组新的配对观测都先更新地图。初始扫描给出左转建议 `linear_x=0, angular_z=0.25`，只累计新配对底盘位姿中的有符号 yaw 增量，正确跨越 ±π；反向转动会减小进度，重复旧观测不推进。默认累计 2π 后进入探索。是否完成由位姿决定，不由消息次数决定。
- 原版实机入口在 `l_step < 35` 时覆盖为转向，没有精确一圈反馈。由于本车允许的转速不同，不能直接照搬步数。此实现是明确的实车适配，不宣称与原版启动时长逐帧一致。
- 扫描超过 45 s 仍未完成，或底盘点落入当前已知障碍的膨胀区，分别输出 `INITIAL_SCAN_TIMEOUT` / `INITIAL_SCAN_BLOCKED`，给出零速度建议、清图并锁存。地图未知部分不能证明旋转空间已验收。
- 现有数据新鲜度、时间配对、位姿跳变、处理超时仍生效。输入中断不能通过累加墙钟时间完成扫描。显式 reset 清地图、目标、扫描进度与缓存，重新等待新数据。

**当前入口仍是只读预览，不实例化 DecisionBridge，不会让车旋转。** 静止时默认会显示扫描建议、进度保持约零，45 s 后超时；这不是扫描成功。只看静止地图/规划时应明确跳过扫描：

```bash
cd ~/workspace/wheeltec_motion_ws
bash scripts/start_exploration_preview.sh --start --skip-initial-scan
```

输出会标明 `initial_scan_skipped=true`、目标转角为零，不伪装成完成一圈。正常流程保留默认 `--start`；实车执行仍待单独接通并验收运动入口。准备好的桥已支持新鲜 `INITIAL_SCAN` 左转决策，测试仅接合成话题。

## 两层地图与前沿

有效 RGB-D 经过现有内外参变换进入 ROS 世界 XY：

1. 所有有效且在地图范围内的三维点投影到 `explored` 层，表示该格已有观测。障碍按本车地面参考点的现有 0.08–1.3 m 高度范围投影到 `obstacle` 层。
2. 对已观测层做 5×5 闭运算，提取最大轮廓；对障碍做 7×7 膨胀，从轮廓中去掉障碍附近的部分及地图外边缘。
3. 按 8 邻域分组，保留严格大于 20 格的组。采用原版 Global_Map_Proc 的质心、稳定面积排序和最多 6 组规则。
4. 在通过底盘通行检查、且尚未进入已有 0.25 m 到达容差的候选中随机选择一个前沿代替 VLM 分配。不使用旧版“离车必须至少 0.45 m”的前沿过滤。已到达的候选不应被每轮重选；FMM 报告到达的目标暂时排除，避免停在 FRONTIER_REACHED 循环。

已观测点层与旧的射线空闲层分开存储。旧 `free` 层仍用于保守对照与可选语义接近检查，不能把它当成论文的 explored 层。默认地图白色表示“已观测、未标记障碍”，黑色障碍，灰色未知；白色不等于车体净空或物理安全已验证。规划不会把未知格写成白色。

## 无前沿与 FMM

默认通行图由现有半径 0.25 m + 余量 0.05 m 膨胀障碍后取反得到，再检查与底盘的连通性；因此**未知区域也可参与规划**。这与此前只能在已知空闲中规划有本质区别。

没有有效前沿时，从整张有界地图随机取点，标记 `goal_source=random_map_fallback`。候选可以落在未知区；最多尝试 64 次，排除膨胀障碍、不可连通、已到达范围和暂时黑名单内的点。全部失败报告 `NO_VALID_RANDOM_GOAL` 并给出零建议，不无限采样，也不把障碍强制改为空闲。重新出现有效前沿时优先替换随机兜底目标。

选中目标后继续使用锁定官方 FMM，校验短期目标和直达短期段；根据底盘朝向产生前进/左右转建议。本车保持 0.10 m/s、0.25 rad/s 建议速度及控制上限 0.15/0.35。当前目标在有效时保留，无进展后按原有 10 s/15 s 规则更换并暂时排除，减少每帧随机跳目标。

## 与原仓库的对应和保留差异

| 环节 | 当前实现 |
| --- | --- |
| 地图表示 | 论文两层点投影；ROS XY、地面底盘参考点与当前相机外参 |
| 前沿几何 | 对齐 Global_Map_Proc.Frontier_Det；有直接读取锁定原方法的结果对比测试 |
| VLM 选择 | 按用户约定用带种子的随机前沿选择替代 |
| 无前沿处理 | 保留原版全图随机取点思路，增加有限次数及有效性检查 |
| 未知通行 | 与原版障碍图规划思路一致；地图上仍标为未知 |
| 初始旋转 | 按反馈累计一圈，替代原版处理步数覆盖转向 |
| 底盘膨胀与目标 | 保留本车半径/余量和目标稳定规则；不照搬原版固定 10 格膨胀、目标强制放行与目标区域扩张 |
| 三维语义/清障 | 未搬入原版完整语义点云、动态清障、碰撞地图或多机流程；现有累计障碍仍是局限 |

因此这是按论文流程和本车约束适配的几何探索基线，不是整个官方 Agent 的逐行移植，也不证明未知空间没有障碍。实车联合验收仍未完成。

## 配置与可视化

配置位于 `src/wheeltec_exploration/config/astra_preview.yaml` 的 map 段：

| 参数 | 默认 / 含义 |
| --- | --- |
| exploration_policy | paper_frontier；known_free 对照旧规划规则，扫描参数独立，完整旧行为须同时设置 initial_scan_angle=0 |
| initial_scan_angle | 6.283185307179586 rad；0 表示显式跳过，不是扫描完成证明 |
| initial_scan_timeout | 45 s；从第一组有效扫描观测开始计时 |
| paper_frontier_min_cells | 20，严格大于该值 |
| fallback_sample_attempts | 64，全图候选尝试上限 |
| frontier_min_cells / goal_min_distance | 3 / 0.45 m，仅 known_free 策略使用 |

`/decision` 新增 phase、scan_progress_rad、scan_target_rad、goal_source、exploration_policy、planning_allows_unknown、initial_scan_skipped。随机前沿与全图随机目标分别是 `random_frontier` 和 `random_map_fallback`，不要混淆。

`/map` 是当前策略的合成地图；`/explored_map` 为点投影层（-1 未观测、0 已观测）；`/obstacle_map` 为二值障碍掩码（100 障碍、0 未标记障碍，0 不能解释成已知空闲）。所有话题均在 `/wheeltec_exploration` 下。map.npz 保存 explored/obstacle/free 三层供复查。

RViz `/debug_markers` 显示青色前沿边缘、黄色候选、绿色目标、橙色短期目标和状态/扫描进度文字。每次先删除上一组标记，标记寿命 0.5 s；故障与退出主动清除。旧 Pose 话题仍兼容，但默认布局关闭其显示，避免遗留箭头误导。
