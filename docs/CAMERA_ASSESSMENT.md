# 当前深度相机检查与 D455 对比

检查日期：2026-10-01。对象为本车连接的 USB 相机；仅枚举设备、查询 SDK 和短时读取图像，不初始化 ROS 运动节点、不发底盘速度，不修改厂家源码、固件或持久设置。每种模式约 5 秒，不能作为长期稳定性或测距精度验收。

## 当前设备

- USB manufacturer=`ORBBEC`，product=`ASTRA S`，VID/PID=`2bc5:0402`。OpenNI 设备名为通用系列名 `Astra`，不是 Astra 2、Astra Stereo S U3，也不是 RealSense D455。
- USB 实际协商速率 480 Mb/s（USB 2.0）。设备通过厂商 USB 接口访问，不是普通 UVC `/dev/video*` 摄像头；没有视频节点不代表没有深度相机。
- 现有厂家 Astra 驱动中的 OpenNI SDK 2.3.0.85 可打开设备，查询固件 5.8.22；未安装新依赖。RealSense 工具返回没有设备，未发现 D455。
- 支持 depth、color、IR；depth 为 16 位毫米格式（OpenNI DEPTH_1_MM），彩色采用 RGB888。ROS 接入时仍须核对驱动发布的实际编码、stride、CameraInfo 和时间戳，不将 SDK 数据格式直接等同于已验证的 ROS 话题。

## 实际读流结果

| 测试模式 | 结果 |
| --- | --- |
| 深度 640×480@30 ＋彩色 640×480@30 | 两流均有图像；预热后约 29.1 / 29.6 fps，主机读帧最大间隔约 44 / 40 ms |
| 深度 640×480@30 ＋彩色 1280×720@30 | 两流均有图像；约 29.1 / 29.6 fps，确认收到 1280×720 RGB888 数据 |
| 深度 1280×1024@7 ＋彩色 640×480@30，同步开启 | 彩色正常，5 秒内未收到深度帧；这个组合不能作为本轮已验证的可用双流模式 |
| 深度 1280×1024@7，彩色不启动 | 读到高分辨率深度，约 7.3 fps；不足以按 30 fps 深度使用 |
| VGA 双流开启深度→彩色配准 | SDK 开启成功，两流持续输出约 29.1 / 29.6 fps；未测实际像素对应误差 |

SDK 声称支持深度→彩色配准和同步，VGA 配准调用成功；这不等于已完成 RGB-D 空间与时间对齐验收。高分辨率彩色的输出尺寸已确认，尚未证明对应的原生有效细节；SDK 列表还有其他模式，本轮未全部试读。SDK 返回深度 FOV 约 58.59°×45.64°。

本次场景 VGA 深度帧非零比例约 25–33%，落在 0.4–2 m 的像素仅约 8–11%；还有超过标称距离的非零深度值（约 9.5–9.8 m）。这些值不能证明短距相机具备可靠远距测量能力，也不能据此认定相机损坏；未控制照明、被测材质和相机朝向，未使用已知距离标靶。建图必须过滤零值和超范围深度，再在实际安装视野验证覆盖率。

短测中部分彩色/配准深度流有一次非递增 SDK 时间戳，尚未定位发生阶段；SDK 也提示 USB 事件线程未取得调度优先级。需在 ROS 接入时检查时间转换、重复帧、RGB-D 配对及长时间丢帧，不能从本轮平均帧率推断长期无丢帧。

## 与计划 D455 的区别

以下 D455 为厂家规格，未连接到本机进行实测；ASTRA S 距离/环境/IMU 为厂家规格，数据流另有本轮实测。

| 项目 | 当前 ASTRA S | 计划 D455 |
| --- | --- | --- |
| 深度原理 | 红外结构光 | 主动双目立体深度 |
| 标称/推荐范围 | 0.4–2 m，短距版本 | 理想范围 0.6–6 m |
| 深度视野 | 官方 58.4°×45.5°，SDK 返回接近 | 87°×58° |
| 深度图像 | 实测 VGA 约 29 fps；高分辨率单流约 7 fps | 最高 1280×720；最高 90 fps，分辨率和帧率依模式变化，不能理解为最高分辨率同时 90 fps |
| 彩色图像 | VGA 与 1280×720 RGB 输出已读到，均约 29.6 fps | 官方 1280×800@30 fps，RGB 与深度均为全局快门 |
| IMU | 官方无 | 有 |
| 使用环境 | 官方室内 | 官方室内/室外，实际效果仍受场景影响 |
| 数据接口 | USB 2.0；OpenNI/Astra 驱动 | USB-C 3.1 Gen 1；RealSense 驱动 |

资料：[Orbbec Astra 系列](https://www.orbbec.com/products/structured-light-camera/astra-series/)、[RealSense D455](https://www.realsenseai.com/products/real-sense-depth-camera-d455f/)。Astra 官方系列页面对普通版本 RGB 标为 VGA；本机 SDK 的 HD 输出已额外试读，型号变体与原生传感器分辨率仍需进一步核实，不混用 Astra Pro Plus/Astra 2 的规格。

## 对 Co-NavGPT2 的意义

由上述能力判断，当前 ASTRA S 可以先推进室内 RGB-D 接入、深度单位/内参/配准、语义感知与建图流程，无须等 D455 才开展这些软件工作。首个工作模式建议彩色＋深度 VGA@30，先静止验收，再由用户进行运动验证。

短距离和较窄视野会限制每帧可观察空间，影响地图覆盖及前沿探索；D455 的更宽视野、较远推荐测距和全局快门更适合计划中的移动探索。但 D455 推荐近距起点约 0.6 m，不是所有近距场景都优于 ASTRA S，不能当作贴近底盘的避障保证。

当前 start_d455.sh 是 RealSense 专用，不能用于 ASTRA S。接入需使用现有 Astra/OpenNI 驱动，并统一彩色、深度、CameraInfo 与时间/坐标约定，不能直接沿用 D455 内参、外参或相机到 IMU 的变换。本轮没有新增 ROS 相机启动项，也没有完成相机与 FAST-LIO 的 TF 链。

原始探针与输出保存在忽略 Git 的 `runtime_logs/camera/20261001-astra-s/`；探针直接使用已有 SDK，未启动上游 Co-NavGPT2 控制入口。
